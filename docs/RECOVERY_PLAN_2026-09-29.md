## 5. 上线前必须面对的问题

1. **真实模型调用阻塞。** 更新 `apps/api/.env` 中现有 provider 的有效凭据/endpoint，然后测试真实卡片和故事板；不要把 key 粘贴到聊天或提交到 Git。401 的具体原因尚未确定，不能直接断言是额度耗尽。若原项目凭据无法恢复，使用已有可用 provider 做适配，记录当前产品实际使用的模型。
2. **参考结构与输出素材耦合。** 当前源视频由卡片追溯决定，导致“学广告 A → 给品牌 B 做视频”仍可能播放 A 的画面。应把 reference card IDs 与 target media job ID 分开。最小版只需支持一条目标视频，不做素材库编辑器。
3. **可控性只存在于 JSON。** 增加场景文案、时长、布局的轻量表单；保存后重新验证并渲染。素材替换由独立目标视频完成，效果先限定为已有 layout/animation 枚举。
4. **公开访问的任务可靠性不足。** 当前请求一直等待子进程，最多 600 秒，没有任务查询接口。增加提交任务即返回 ID、后台串行处理、持久化状态、轮询、失败重试、刷新恢复；进程重启后把中断任务标记为可重试。限定单实例、一个渲染 worker。
5. **不能直接开放当前数据目录。** 全 `DATA_DIR` 被 `/static` 挂载；没有用户归属；省略 source IDs 会读全库最新卡。试用版需要独立 session/邀请凭据、资源归属验证、公共示例库与个人素材分离；下载同样做授权。UUID 不是授权机制。
6. **成本边界缺失。** 提议试用版先限制上传 ≤30 秒/30 MB、输出 15–20 秒/720p、渲染并发 1、每个试用 session 3 次、全站初始 10 次额度。额度在服务端验证，模型和渲染失败不自动无限重试。数值是初始产品配置，后续按实测调整。

## 6. 收窄后的 MVP

**目标用户假设**：有自己的产品/品牌素材、需要反复做短视频的个人内容运营者。尚未做用户研究，不能声称需求已被验证。

**要完成的用户任务**：把一个参考广告的组织方式，应用到自己的素材，得到一个可修改、可导出的 15–20 秒草稿。

建议前台主流程：选择参考结构/示例 → 输入品牌、卖点、CTA 与上传自己的短素材 → 生成草稿 → 改文案/时长/布局 → 导出。

原五步链路保留在“查看分析过程”中；第一次访问可点示例体验，避免没有素材的访客被挡在上传页。自动分析只描述当前真实信号；演示库中的人工校正卡要标明来源与人工校正，不能冒充模型视觉理解。

**上线验收线：**

- [ ] 新访客通过 HTTPS 打开页面，并在没有讲解的情况下知道下一步。
- [ ] 示例体验能跑通；同时允许试用者输入自己的 brief / 目标素材。
- [ ] 至少展示 3 张有区别的参考结构卡；能说明卡片来源。
- [ ] 输出使用目标素材，不因选了参考卡就播放其他人的视频。
- [ ] 文案和时长改动反映到保存后的故事板及下一次成片中。
- [ ] 得到可播放、可下载的 MP4；不把占位背景或 mock 文案作为 AI 成功产出。
- [ ] 等待时可见真实任务状态，刷新可恢复；失败可重试。
- [ ] 两个不同 session 无法读取或引用对方的私有上传、卡片和成片。
- [ ] 成本额度有效；重复点击不会开启多个相同渲染。
- [ ] 在部署环境用 3 个不同 brief 连续完成生成；记录各步耗时、错误与成本。
- [ ] 一段 60–90 秒演示录像和两个已导出样片作为面试备份。

**两天不做：** Seedance/其他生成视频 API、复杂音频分析、完整时间线剪辑器、多模型 agent 编排、自动证明“爆款”、付费订阅、大规模向量索引、微服务迁移。

最小音频处理可以排在成片质量修整中：有权使用的单条 BGM/明确静音选项。节拍识别和自动配乐以后再做。

## 8. PostgreSQL/pgvector 原型：做到哪里才算真的有

最新简历写的是“Designed and prototyped”，不要求两天建成生产 RAG 平台，但需要可运行证据。当前仓库没有它。

建议用 Supabase 的免费 PostgreSQL，启用 pgvector；数据库能力已有官方支持。对当前项目，先做卡片级检索，不做独立 atom 向量库。

最小实现范围：

1. 保存 card ID、原始结构 JSON、检索文本、embedding、embedding model/version、来源和 owner/public 标记。
2. 检索文本来自 pattern、hook、叙事、CTA、节奏与规则。embedding 使用确定的可用模型/接口；先核对官方调用契约，不假设现有 Seed endpoint 能做 embedding。
3. 对 3–6 张有区别、经人工检查的卡片生成真实 embeddings；用户 brief 用同一模型编码，SQL 做 cosine 距离 Top-K。小数据集无需先建近似索引。
4. 检索必须先按 session/公共库筛选，再取 Top-3；展示匹配卡片、来源和使用原因，把实际命中的卡传给故事板 planner。
5. 用 5 个 brief 比较“最近 3 张”与语义 Top-3，保存结果和人工相关性判断。样本太小，不能声称有统计意义的提升。
6. 数据库不可用时明确提示并回退到用户手动选择/预置卡，不跨用户读取全库。

原型完成证据：migration SQL、导入脚本、一次可重复的查询、UI 命中列表、对应 storyboard 的 card IDs、失败回退测试。数据库迁移不是这两天全部数据存储工作的前提。

## 9. 部署方案与 $20 预算

**建议方案：免费数据库 + 短期付费的单实例 Docker 服务。** 优先减少需要维护的进程和平台。前端当前主页可预渲染，可验证 Next 静态导出后由同一个服务提供页面；FastAPI 和 Remotion 运行在同一个容器，渲染串行。若静态导出不顺利，保留 Next，前端单独静态/网页托管，不重写前端。

Docker 使用 Debian 系，包含 Python、Node、Chromium 依赖、Remotion browser cache 和中英文字体；构建时完成安装，运行时不临时下载浏览器。Remotion 官方提供了 Docker 与 CJK 字体配置参考。

Render 是一个具体可选承载：Docker web service + 持久盘。建议先验证 1 CPU / 2 GB、720p、并发 1；实际是否足够以云端渲染测试为准，不承诺 Mac 上的 19 秒速度可以复现。数据目录挂到持久盘，部署时不要把本机 `.env` 或私有历史上传烘焙到镜像。

官方定价检索显示该档约 $25/月、compute 按实际时间折算；只运行约三天的计算资源基础费用约 $2.50（按 30 天估算），仍要另算磁盘、流量和模型。这里是计划估算，不是已经购买，也不是固定封顶报价。超过演示窗口持续运行会继续计费；上线时明确关闭/续用安排并检查账单。

预算分配上限：托管/磁盘/流量 $8；模型与 embedding $5；其余 $7 作为容量调整与故障余量。应用总额度耗尽后停止新的付费任务，保留历史结果查看。不要假设云平台的构建额度设置可以自动封顶所有费用。

免费 Render web service 会休眠，且不能挂持久盘，当前文件型数据不能原样放上去当稳定试用版。静态展示可以免费，视频计算和可靠持久化要单独解决。

依赖用户后续完成的配置：有效模型凭据、可用部署账号/支付方式（若启用付费实例）、数据库账号或现有连接。当前不需要自定义域名。

## 10. 获取第一批反馈与 PM 面试材料

现在没有确定试用用户，不能把“部署完”当成“用户验证”。目标是 3–5 次 10–15 分钟观察，优先找到至少 1 位做过社媒内容的人；其他朋友的结果只用于可用性，不用于验证付费需求。由用户本人发邀请；本轮没有向任何人发送信息。

给试用者一个任务：“用自己的产品/社团/活动素材做一条 15 秒介绍，改一句你不喜欢的字幕，导出成片。”先不教操作，记录卡住的位置、解释成本和最终产物。

建议记录：

| 指标 | 定义 |
| --- | --- |
| 端到端完成 | 实际导出有效 MP4 的人数 / 开始任务的人数 |
| 首次成片耗时 | 开始体验到第一次成功成片；另记等待与编辑时间 |
| 结果接受度 | 愿意直接发布 / 小改后发布 / 不愿使用，附原因 |
| 可控性 | 用户能否完成指定字幕/时长修改并在输出中看到效果 |
| 单次成本与错误 | 实际模型调用成本、渲染时长、重试次数和失败阶段 |

初始可用性目标可以设为 3 人中至少 2 人无需你接管即可导出，20 秒片在 5 分钟内完成；这些是验收目标，不能预先写成结果。若比较“省时”，需要与相同用户的手动制作基线比较，不能猜一个百分比。

面试准备三段故事，每段用真实证据回答：

1. **定义问题与收窄用户。** 为什么聚焦已有素材的内容运营者；目前哪些是观察、哪些仍是假设。
2. **优先级与取舍。** 为什么先做可解释结构、可编辑草稿和可靠导出；为什么推迟生成式视频、beat detection 和完整编辑器。
3. **反馈与迭代。** 谁在哪一步失败/不满意，如何决定先修什么，修改后观察到了什么。没有得到反馈时，明确说尚未验证。

谈 AI 时解释：Seed 做规划与文案，Storyboard JSON 给用户审核和控制的机会，Remotion 执行合成；结构相似不意味着广告效果更好，“viral”目前不是经过实验验证的结果承诺。
